# حروف مع رجا 🔤

لعبة **خلية الحروف**: لوحة من مسدسات، في كل مسدس حرف، وكل حرف له سؤال إجابته
تبدأ بذلك الحرف. فريق يحاول وصل سلسلة من **أعلى اللوحة إلى أسفلها**، والفريق
الآخر من **اليمين إلى اليسار**. أول من يُكمل سلسلته يفوز بالجولة.

بُنيت بـ HTML و CSS و JavaScript خام — **بدون أي مكتبة أو أداة بناء**.

---

## التشغيل

اللعبة تقرأ بنك الأسئلة عبر `fetch`، والمتصفح يمنع ذلك عند فتح الملف مباشرة
بالنقر المزدوج (سياسة `file://`). لذلك **لا بد من خادم محلي**:

```bash
python -m http.server 8210 --bind 127.0.0.1
```

ثم افتح: <http://127.0.0.1:8210>

لو ظهر تحذير أحمر في الصفحة الرئيسية فمعناه أنك فتحت الملف مباشرة.

---

## خريطة الملفات

```
index.html            كل الشاشات: الرئيسية، كيف نلعب، الإعدادات، اللعب، النهاية
css/style.css         التنسيق كاملاً (فيه قسم الجوال في الأسفل)
js/utils.js           الصوت، التخزين، الشاشات، الإشعارات والنوافذ
js/hive.js            هندسة الخلية وكشف الاتصال — منطق خالص بلا DOM
js/game.js            حالة اللعبة، الجولات، الأدوار، قواعد الإجابة
js/ui.js              الرسم فقط: اللوحة، نافذة السؤال، النتائج
js/setup.js           شاشة الإعدادات والإقلاع
data/questions.json   بنك الأسئلة — 280 سؤالاً في 28 حرفاً
```

**الفصل مقصود:** `hive.js` لا يعرف شيئاً عن اللعبة، و`game.js` لا يلمس الشاشة،
و`ui.js` لا يقرّر أي قاعدة. أي باق تعرف في أي ملف تبحث عنه.

## ثلاث حقائق تقنية تستحق المعرفة

### 1. اللوحة تضمن فائزاً واحداً دائماً

اللوحة المعبّأة بالكامل بفريقين لا يمكن أن تنتهي بتعادل، ولا يمكن أن يفوز
الفريقان معاً. تم التحقق بمحاكاة **200,000 لوحة عشوائية: صفر تعادل وصفر
فوز مزدوج** في كل المقاسات من ٤×٤ إلى ٧×٧.

الاستثناء الوحيد قاعدة «الخلية تُقفل»، لأن القفل يحذف خلايا من الطرفين فتنكسر
الضمانة. اللعبة تتعامل مع هذه الحالة (الفوز لصاحب الخلايا الأكثر) لكنها ليست
الافتراضية.

### 2. الاتجاه العمودي كان أفضل — والتبديل يصلحه

المسدسات تتداخل رأسياً (المسافة بين الصفوف = ¾ الارتفاع لا الارتفاع كاملاً)،
فاللوحة «المربعة» أعرض فعلياً مما هي عالية، والمسار العمودي أقصر. القياس على
لوحة ٥×٥: **العمودي يفوز 53٪ مقابل 47٪**.

لا يوجد مقاس صحيح يعطي 50/50 بالضبط (جرّبنا: ٥×٤ ← 42٪، ٦×٥ ← 45٪، ٨×٧ ← 49٪).
لذلك بقيت اللوحة مربعة — وهي الأجمل شكلاً — و**يتبادل الفريقان الاتجاهين كل
جولة** فيلغي الانحياز نفسه على مدى المباراة.

### 3. الإحداثيات محورية داخلياً وإن كان العرض بصفوف مُزاحة

الشبكة تُرسم بصفوف مُزاحة (`odd-r`) لأن هذا ما يعطي الشكل المطلوب. لكن حساب
الجيران في هذا النظام يختلف حسب فردية الصف، وهو مصدر أخطاء كلاسيكي. لذلك تُحوَّل
كل خلية مرة واحدة عند البناء إلى إحداثيات محورية حيث **الجيران ستة اتجاهات
ثابتة لا تتغيّر أبداً**.

ولاحظ أن `hive.js` لا يحوي أي تعامل مع RTL. «من اليمين لليسار» و«من اليسار
لليمين» شرط واحد رياضياً — المهم أن تلمس السلسلة الحافتين. خلط اتجاه العرض
بمنطق اللعبة مصدر أخطاء لا ينتهي.

## اختصارات المقدّم

| المفتاح | الأثر |
|---|---|
| `مسافة` أو `Enter` | اعرض الإجابة |
| `1` | إجابة صحيحة |
| `2` | إجابة خاطئة |

لا يوجد اختصار لإغلاق نافذة السؤال — إغلاقها بلا حكم يعني تهرّباً من السؤال.

## توسيع بنك الأسئلة

`data/questions.json` بهذا الشكل:

```json
{
  "letters": {
    "ب": [
      { "q": "عاصمة لبنان", "a": "بيروت" }
    ]
  }
}
```

الشروط:
- **الإجابة تبدأ بحرفها** (أل التعريف تُتجاهل: «الرياض» تحت حرف ر)
- كل حرف بلا أسئلة يُستبعد تلقائياً فلا تظهر خلية بلا سؤال
- اللعبة لا تكرر سؤالاً داخل المباراة الواحدة حتى تنفد أسئلة الحرف

للتحقق من صحة البنك بعد أي إضافة:

```bash
node -e "const j=JSON.parse(require('fs').readFileSync('data/questions.json','utf8')).letters;const n=s=>{s=s.trim();if(/^ال/.test(s)&&s.length>3)s=s.slice(2);return s.replace(/[أإآ]/g,'ا')};let bad=[];for(const[l,v]of Object.entries(j))for(const q of v)if(n(q.a)[0]!==l.replace(/[أإآ]/g,'ا'))bad.push(l+' → '+q.a);console.log(bad.length?bad.join('\n'):'✅ سليم')"
```
